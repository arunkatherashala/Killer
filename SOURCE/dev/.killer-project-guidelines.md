# Killer Project - File Organization Guidelines

## Directory Structure Rules

### Root Directory (Keep Clean)
**ONLY these types of files in root:**
- `README.md` - Main project overview
- `RELEASE_NOTES_*.md` - Version release information
- `requirements-dev.txt` - Python dependencies
- `*.sln` - Solution files
- `.gitignore`, `.env`, etc. - Git & config files

**NOTHING ELSE** should be in root directory.

---

## File Organization by Type

### 📄 Documentation Files → `docs/` folder

**Rules:**
- ALL `.md` documentation goes to `docs/`
- Include: guides, architecture, API reference, tutorials
- No documentation in root directory
- Create subdirectories in docs/ as needed for organization

**Examples:**
```
docs/
├── NATIVE_COMPILATION_GUIDE.md
├── PERFORMANCE_OPTIMIZATION.md
├── TYPE_SPECIALIZATION_ARCHITECTURE.md
└── [any other guides]/
```

---

### 🧪 Test Files → `tests/` or `dev/testing/` folder

**Rules:**
- ALL `.killer` test files go to `tests/`
- ALL temporary test scripts go to `dev/testing/`
- ALL language benchmark files go to `dev/testing/benchmarks/`
- No test files in root directory

**Examples:**
```
tests/
├── killer/
│   └── *.killer
├── python/
│   └── *.py
└── nativekiller/
    └── *.killer

dev/testing/
├── benchmarks/
│   ├── benchmark.py
│   ├── benchmark_csharp.cs
│   └── benchmark_rust.rs
└── [other temporary tests]/
```

---

### 💻 Source Code → `src/` folder

**Rules:**
- ALL source code goes to `src/`
- Organize by language/version (e.g., `src/v1-python/`, `src/v2-rust/`)
- No source files in root directory

---

### 📚 Examples → `examples/` folder

**Rules:**
- ALL example programs in `examples/`
- Keep examples organized by feature/number
- Examples should be working demonstrations

---

### 🔧 Development & Utilities → `dev/` folder

**Rules:**
- Scripts, tools, and utilities in `dev/`
- Testing infrastructure in `dev/testing/`
- Legacy code in `dev/legacy/`

---

## When Creating New Files

### Before Creating:
1. ✅ Is it a test file? → Put in `tests/` or `dev/testing/`
2. ✅ Is it documentation? → Put in `docs/`
3. ✅ Is it source code? → Put in `src/`
4. ✅ Is it an example? → Put in `examples/`
5. ✅ Is it a tool/utility? → Put in `dev/`
6. ❌ Never put anything in root unless it's essential (README, requirements, config)
