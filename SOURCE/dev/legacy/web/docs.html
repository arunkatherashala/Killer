Introduction

Killer is a modern programming language designed from scratch with focus on simplicity, readability, and modern syntax. It combines features from JavaScript, Python, and other modern languages.

Key Features

Modern Syntax Arrow functions, template literals, classes
Full OOP Classes, inheritance, static methods, getters/setters
Powerful Built-ins Math object, 14+ String methods, 9+ Array methods
Multi-target Execute or transpile to Python/JavaScript

Architecture & Design

The Killer language is built on a three-stage compilation architecture: Lexical Analysis → Parsing → Execution (or Transpilation).

Design Philosophy

  • Simplicity First: Clean, readable syntax inspired by Python and JavaScript
  • Modern Features: Arrow functions, classes, template literals out of the box
  • Multi-Target: Execute directly or transpile to Python/JavaScript
  • Extensible: Modular design allows adding new features easily

Compilation Pipeline

Source Code (.killer)
        ↓
   [LEXER] → Tokenization (70+ token types)
        ↓
   [PARSER] → AST Building (25+ AST node types)
        ↓
      ┌─────────────────────────┬───────────────┐
      ↓                         ↓               ↓
 [INTERPRETER]  [PYTHON TRANSPILER]  [JS TRANSPILER]
    Direct         Python Code          JavaScript
 Execution          (.py)                   (.js)
      ↓                         ↓               ↓
   Output          Python Execution   Node.js Execution

Core Components

1. Lexer (555 lines)

Responsibility: Convert source code into tokens
Token Types: 70+ (keywords, operators, identifiers, literals, etc.)
Key Features: String interpolation support, regex patterns, number parsing

2. Parser (1085 lines)

Responsibility: Build Abstract Syntax Tree (AST) from tokens
AST Nodes: 25+ node types (expressions, statements, declarations)
Key Features: Recursive descent, operator precedence, error recovery

3. Interpreter (1304 lines)

Responsibility: Execute AST directly
Features: Variable scoping, function calls, class instantiation, OOP inheritance
Built-ins: Math object, String methods (14), Array methods (9)

4. Python Transpiler (759 lines)

Responsibility: Convert AST to Python code
Output: Valid, executable Python 3 code
Mappings: Classes → Classes, arrow functions → lambda/def, template literals → f-strings

5. JavaScript Transpiler (535 lines)

Responsibility: Convert AST to JavaScript code
Output: Valid ES6 JavaScript
Direct Mapping: Most Killer syntax translates 1:1 to JS

Execution Pipeline Details

Direct Interpretation Flow

$ python main.py script.killer
1. Read script.killer
2. Lexer: text → tokens
3. Parser: tokens → AST
4. Interpreter: execute AST
5. Output results

Python Transpilation Flow

$ python main.py --python script.killer
1. Read script.killer
2. Lexer: text → tokens
3. Parser: tokens → AST
4. Python Transpiler: AST → Python source
5. Write to stdout (or file)
6. User runs: python output.py

JavaScript Transpilation Flow

$ python main.py --js script.killer
1. Read script.killer
2. Lexer: text → tokens
3. Parser: tokens → AST
4. JS Transpiler: AST → JavaScript source
5. Write to stdout (or file)
6. User runs: node output.js

Design Patterns Used

Visitor Pattern

The interpreter uses a visitor pattern to traverse and execute the AST. Each node type has a corresponding evaluation method.

Symbol Table

Variables and functions are stored in scope-based symbol tables. Each function creates a new scope, supporting closures.

Recursive Descent Parsing

The parser uses recursive descent to handle operator precedence and nested expressions elegantly.

Code Generation

Transpilers walk the AST and generate target language code string by string, maintaining proper indentation and structure.

Performance Characteristics

Operation Time Complexity Notes
Lexical Analysis O(n) Single pass through source code
Parsing O(n) Single pass, recursive descent
Variable Lookup O(d) d = scope depth (usually small)
Array Operations O(n) Same as native Python/JS
Optimization Tips:
• Use transpilation for production (Python/JS execution is faster)
• Direct interpretation is best for quick testing and prototyping
• Array methods are optimized and as fast as native implementations
